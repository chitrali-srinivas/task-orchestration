1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
This deep product audit investigates the Mobile Preview / Runtime Preview system
of Survey Builder V1.1 (src/app/layouts/survey-builder-simplified/components/preview/).
The Mobile Preview represents the mission-critical respondent experience for field
enumerators and farmers on mobile devices.

Summary of Audit Findings:
* Critical Navigation Bug Root Cause Identified (MOBILE-NAV-001 - P0 Blocker):
  - In PreviewRuntime (preview-runtime.tsx, lines 97-106), an active useEffect
    watches [selectedQuestionId, visibleQuestions]. When a respondent answers a
    question in the preview or when conditional questions appear/disappear,
    runtimeAnswers updates in the parent page, recomputing visibleQuestions.
  - Because visibleQuestions receives a new array reference on every answer
    mutation, the effect immediately executes:
    setCurrentQuestionIndex(visibleQuestions.findIndex(q => q.id === selectedQuestionId))
  - Since selectedQuestionId remains pinned to whichever question was selected in
    the desktop builder (e.g. Q1), answering Q2, Q3, or any follow-up question
    immediately forces currentQuestionIndex back to Q1 (0), resetting the screen
    to Q1's default state or jumping backward.
* Index-Based Navigation vs Dynamic Question Sequence (MOBILE-NAV-002 - P1 Critical):
  - Runtime navigation relies on integer pointer arithmetic (currentQuestionIndex + 1)
    rather than tracking the active question by stable questionId. When answers
    dynamically expand or contract the visibleQuestions array (via follow-ups or
    visibility rules), the active pointer shifts under the user's feet.
* Repeater Instance State & Navigation Desync (MOBILE-REPEATER-001 - P1 Critical):
  - When completing the final question of a repeated section (e.g. Plot 1 of 2),
    activeRepeaterTab increments and forces currentQuestionIndex to the first child
    index. However, if the first child is conditionally hidden in Plot 2, findIndex
    returns -1, freezing navigation.
* Component Remounting & Local State Disconnect (MOBILE-STATE-001 - P2 Major):
  - In preview-polygon.tsx, vertices are initialized in local useState without
    syncing with the incoming value prop across Next/Previous transitions.
* Accessibility & Touch Constraints (MOBILE-A11Y-001, MOBILE-UI-001 - P2 Major):
  - Top navigation in the smartphone simulator lacks ARIA live announcements on
    question transitions, and radio button tap targets fall below the 44x44px
    WCAG touch target guideline.

2. MOBILE PREVIEW ARCHITECTURE
--------------------------------------------------------------------------------
1. Current Question Source of Truth:
   Integer currentQuestionIndex pointing into derived visibleQuestions array
   (preview-runtime.tsx, line 65).
2. Answer Data Source of Truth:
   runtimeAnswers dictionary stored in page.tsx (line 80) and updated via
   onChangeAnswer(questionId, value).
3. Visible Questions Source of Truth:
   useMemo filter evaluating isQuestionVisible(q, runtimeAnswers) against all
   survey.questions (preview-runtime.tsx, lines 76-94).
4. Follow-Up Relationships:
   Declarative evaluation in lib/logic-evaluator.ts matching parent trigger
   rules and conjunction groups.
5. Repeater Instances:
   Scoped keys in runtimeAnswers formatted as ${questionId}_inst_${activeRepeaterTab}.
6. Navigation Triggers:
   handleNext (line 146) and handleBack (line 274) calculating index offsets.
7. Component Mounting:
   Direct invocation of renderPreviewField(activeQuestion, currentAnswer, ...)
   without React key boundaries on the card wrapper.

3. CRITICAL NEXT / PREVIOUS INVESTIGATION (ROOT CAUSE)
--------------------------------------------------------------------------------
Finding: MOBILE-NAV-001 (Severity: P0 Blocker)

Concrete Reproduction Sequence:
1. In the desktop Survey Builder, select Q1 in the left question list (selectedQuestionId = "q_1").
2. Look at the Mobile Preview on the right: Q1 ("Are you a farmer?") is displayed at currentQuestionIndex = 0.
3. Click Next on the Mobile Preview:
   - handleNext increments currentQuestionIndex to 1.
   - The preview correctly displays Q2 ("What is your farm size in acres?").
   - Crucial note: selectedQuestionId in page.tsx is still "q_1" because handleNext only updates local index state.
4. On Q2, the user enters an answer (e.g. types 25 or clicks a choice).
5. The input calls onChangeAnswer("q_2", 25).
6. Parent page.tsx executes setRuntimeAnswers(prev => ({ ...prev, q_2: 25 })).
7. PreviewRuntime re-renders with the updated runtimeAnswers prop.
8. visibleQuestions useMemo executes and generates a NEW ARRAY REFERENCE.
9. The useEffect at lines 97-106 fires because visibleQuestions is in its dependency array:
   useEffect(() => {
       if (!selectedQuestionId) return;
       const targetIdx = visibleQuestions.findIndex((q) => q.id === selectedQuestionId);
       if (targetIdx !== -1) {
           setCurrentQuestionIndex(targetIdx);
           setIsSubmitted(false);
           setValidationError(null);
       }
   }, [selectedQuestionId, visibleQuestions]);
10. selectedQuestionId is "q_1". targetIdx evaluates to 0.
11. setCurrentQuestionIndex(0) is invoked!
12. ACTUAL OBSERVED BEHAVIOR: The user typed an answer into Q2, and the screen
    IMMEDIATELY SNAPPED BACK TO Q1 IN ITS DEFAULT STATE.

Recommended Fix:
1. Remove visibleQuestions from the selectedQuestionId effect, or track
   prevSelectedQuestionIdRef so it only syncs when the user explicitly clicks a
   different question in the desktop tree.
2. Maintain activeQuestionId (string) as primary state instead of array index.
